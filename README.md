# 🐾 Учет домашних животных — Docker Compose (Вариант 31)

Лабораторная работа по теме **«Контейнеризация многокомпонентных приложений с помощью Docker Compose»**.

**Индивидуальный вариант 31 — «Учет домашних животных»:**
- Web-сервис: **расчет суточной нормы кормления по весу и возрасту питомца**;
- данные для БД: **медкарта и карточка питомца**.

## Архитектура (4 контейнера)

| Контейнер     | Технология              | Назначение                                                                 |
|---------------|-------------------------|----------------------------------------------------------------------------|
| `frontend`    | Nginx + HTML/CSS/JS     | Веб-интерфейс, порт **8081**. Nginx проксирует `/api` к backend            |
| `backend`     | Python (Flask)          | REST API: CRUD с PostgreSQL, вызов Web-сервиса, порт 5000 (внутр.)         |
| `db`          | PostgreSQL 16           | Хранение карточек питомцев, медкарт и журнала расчетов, том `pgdata`       |
| `web-service` | Python (Flask)          | Микросервис-эмулятор: расчет нормы кормления (RER/MER), порт 5001          |

Все контейнеры объединены стандартной мостовой (bridge) сетью Docker Compose.
Порядок запуска задан через `depends_on` с healthcheck-проверкой готовности PostgreSQL.

## Возможности веб-интерфейса

- **Кнопка 1 — «Показать моих питомцев»**: запрос к внутренней БД через backend
  (`GET /api/pets`), таблица карточек питомцев; по кнопке «Медкарта» открывается
  медкарта питомца (`GET /api/pets/{id}/medcard`).
- **Кнопка 2 — «Рассчитать норму кормления»**: backend запрашивает специализированный
  Web-сервис (`POST /api/calculate`) и **сохраняет результат в БД**
  (`feeding_history`), после чего результат выводится на экран.
- Блок «История расчетов» показывает последние записи журнала из БД.

## API

| Метод | Путь                        | Описание                                                  |
|-------|-----------------------------|-----------------------------------------------------------|
| GET   | `/api/health`               | Проверка готовности backend и состояния БД                |
| GET   | `/api/pets`                 | Список карточек питомцев из БД                            |
| GET   | `/api/pets/{id}/medcard`    | Медкарта выбранного питомца                               |
| GET   | `/api/feeding-history`      | Журнал расчетов нормы кормления                           |
| POST  | `/api/feeding/calculate`    | Расчет через Web-сервис + запись результата в БД          |
| POST  | `web-service:5001/api/calculate` | Web-сервис: норма кормления по весу, возрасту и виду  |

Пример запроса к Web-сервису:

```json
{ "species": "dog", "weight_kg": 28.5, "age_years": 3 }
```

Ответ:

```json
{
  "rer_kcal": 801.7,
  "daily_kcal": 1443.1,
  "daily_food_g": 390.0,
  "meals_per_day": 2,
  "advice": "..."
}
```

Расчет использует ветеринарные формулы:
`RER = 70 × масса(кг)^0.75`, `MER = RER × коэффициент активности` (зависит от вида и
возрастной группы: молодой / взрослый / пожилой), норма сухого корма = `MER / 3.7 ккал·г⁻¹`.

## База данных

При первом старте PostgreSQL автоматически выполняется `db/init.sql`:
создаются таблицы `pets` (карточка питомца, имена уникальны — `UNIQUE`),
`medcard` (медкарта) и `feeding_history` (журнал расчетов) и вносятся первичные
данные (4 питомца, записи медкарты и истории). Данные сохраняются в именованном
томе `pgdata`.

## Запуск

Требования: Docker Desktop (Docker Engine + Docker Compose).

```bash
docker compose up --build
```

Или в фоновом режиме:

```bash
docker compose up -d --build
```

После запуска откройте в браузере: **http://localhost:8081**

Остановка и очистка:

```bash
docker compose down          # остановить контейнеры
docker compose down -v       # остановить и удалить том с данными БД
```

## Переменные окружения

Переменные задаются в `docker-compose.yml` и могут быть переопределены в файле `.env`
(см. `.env.example`): `POSTGRES_USER`, `POSTGRES_PASSWORD`, `POSTGRES_DB`,
а также `DB_HOST/DB_PORT/DB_NAME/DB_USER/DB_PASSWORD` и `WEB_SERVICE_URL` для backend.
